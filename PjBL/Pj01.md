## 1. 🎯 O Grande Desafio (Contextualização PjBL)

Imagine que você foi contratado(a) para trabalhar na equipe de desenvolvimento de um **editor de texto colaborativo** (algo parecido com o Google Docs). Uma das funcionalidades mais importantes — e que os usuários mais reclamam quando falha — é o botão **"Desfazer" (Ctrl+Z)** e **"Refazer" (Ctrl+Y)**.

Sua primeira ideia, como boa parte dos desenvolvedores iniciantes, foi usar um **Array** para guardar o histórico de ações:

```java
String[] historico = new String[100]; // 😬 Ué, por que 100? E se o usuário digitar mais que isso?
```

E aqui já começam os problemas:

### 🚨 Problema 1: Tamanho fixo
Arrays em muitas linguagens (ou estruturas baseadas neles) têm um tamanho definido na criação. Se o usuário digitar/desfizer mais ações do que o previsto, o sistema quebra ou você precisa **recriar um array maior e copiar tudo** — uma operação cara.

### 🚨 Problema 2: Inserir e remover no meio é caro
Quando o usuário desfaz uma ação no **meio** do histórico e depois faz algo novo, você precisa **remover todos os itens à frente** e possivelmente **deslocar elementos** na memória. Em um array, remover ou inserir um elemento no início ou no meio custa, em média, **O(n)** — ou seja, quanto maior o histórico, mais lento fica.

### 🚨 Problema 3: Desperdício de memória
Se você aloca um array gigante "só para garantir", e o usuário só usa 3 posições, está desperdiçando memória à toa.

### 💡 Por que precisamos de uma nova estrutura?

Precisamos de uma estrutura de dados que:
- Cresça e diminua **dinamicamente**, conforme a necessidade real de uso;
- Permita inserir e remover elementos no início (ou em qualquer ponto) de forma **rápida (O(1))**, sem precisar deslocar todo mundo;
- Não exija saber o tamanho final de antemão.

É exatamente isso que a **Lista Encadeada (Linked List)** resolve. Ela é a estrutura de dados perfeita para representar sequências que crescem e diminuem de forma imprevisível — como o histórico de "desfazer/refazer", uma playlist de músicas ou o histórico de navegação de um browser.

**Sua missão a partir de agora:** entender como essa estrutura funciona por dentro e implementá-la com suas próprias mãos.

## 2. 🧩 A Anatomia de uma Lista Encadeada (Visual e Conceitual)

Esqueça por um momento a ideia de "posições numeradas" (índice 0, 1, 2...) que você usa em arrays. Uma Lista Encadeada funciona de um jeito bem diferente — e mais parecido com a vida real do que você imagina.

### 🚂 Analogia: Vagões de um trem

Pense em um **trem**. Cada **vagão** carrega:
1. Uma **carga** (o dado que você quer guardar — ex: o texto digitado, o nome da música);
2. Um **gancho** que se conecta ao **próximo vagão**.

O maquinista (o programa) não precisa saber quantos vagões existem no trem. Ele só precisa saber **qual é o primeiro vagão** (a "cabeça" do trem). A partir dali, ele anda vagão por vagão, seguindo o gancho, até não encontrar mais nenhum vagão conectado (o **fim da linha**).

### 🗺️ Analogia: Caça ao tesouro

Também pense em uma **caça ao tesouro**: você recebe uma pista que diz onde está o próximo item, e aquele item contém outra pista para o próximo, e assim por diante, até chegar ao tesouro final (que não aponta para mais nada).

### 📦 Os três conceitos-chave

| Conceito | O que é | Analogia |
|---|---|---|
| **Nó (Node)** | A unidade básica da lista. Cada nó é um "vagão" ou uma "pista". | O vagão do trem |
| **Dado (Data)** | A informação real que queremos armazenar dentro do nó. | A carga do vagão |
| **Próximo (Next)** | Uma referência (ponteiro) que aponta para o **próximo nó** da sequência. Se não houver próximo, aponta para `null` (fim da linha). | O gancho que conecta ao vagão seguinte |

Visualmente, uma Lista Encadeada com 3 elementos se parece com isto:

```
[ HEAD ] -> [ Dado: "Música A" | Next ] -> [ Dado: "Música B" | Next ] -> [ Dado: "Música C" | Next: null ]
```

Repare que:
- Só guardamos uma referência para o **primeiro** nó (`head`);
- Cada nó "sabe" apenas quem vem depois dele — não existe índice numérico;
- O último nó aponta para `null`, indicando o fim da lista.

> 💭 **Pense nisso:** se eu quiser inserir um novo elemento **no início** da lista, eu só preciso criar um nó novo e apontar seu `next` para o antigo primeiro nó. Não preciso "empurrar" ninguém! Compare isso com um array, onde inserir no início significa deslocar **todos** os elementos uma posição para a direita.

## 3. 💻 Passo a Passo da Implementação (Mão na Massa)

Vamos implementar uma **Lista Encadeada Simples (Singly Linked List)** em **Java**. Abra seu editor, crie um arquivo chamado `ListaEncadeada.java` e vá digitando (não copie e cole — digitar ajuda a fixar!) enquanto lê os comentários.

```java
/**
 * Lista Encadeada Simples (Singly Linked List) de Strings.
 * Representa, por exemplo, o histórico de ações de um editor de texto.
 */
public class ListaEncadeada {

    // ------------------------------------------------------------------
    // 1) A CLASSE DO NÓ (NODE)
    // ------------------------------------------------------------------
    // Cada Nó é um "vagão do trem": carrega um dado e uma referência
    // para o próximo vagão. Quando não há próximo, "next" vale null.
    private static class No {
        String dado;   // A carga do vagão (o conteúdo armazenado)
        No proximo;    // O gancho que aponta para o próximo vagão (ou null)

        No(String dado) {
            this.dado = dado;
            this.proximo = null; // Todo nó novo nasce sem conexão até ser inserido
        }
    }

    // ------------------------------------------------------------------
    // 2) A ESTRUTURA DA LISTA
    // ------------------------------------------------------------------
    // A lista não guarda "todos" os nós diretamente. Ela guarda apenas
    // a referência para o PRIMEIRO nó (head). É a partir dele que
    // percorremos todo o restante da estrutura, vagão por vagão.
    private No head;   // Ponteiro para o primeiro nó da lista (null se a lista estiver vazia)
    private int tamanho; // Contador auxiliar para sabermos quantos elementos existem

    public ListaEncadeada() {
        this.head = null;
        this.tamanho = 0;
    }

    // ------------------------------------------------------------------
    // 3) INSERÇÃO NO INÍCIO — custo O(1)
    // ------------------------------------------------------------------
    // Para inserir no início, NÃO precisamos deslocar nenhum elemento
    // (diferente do array!). Basta:
    //   a) criar o novo nó;
    //   b) fazer o novo nó apontar para o antigo primeiro nó;
    //   c) atualizar a "head" da lista para o novo nó.
    public void inserirNoInicio(String dado) {
        No novoNo = new No(dado);
        novoNo.proximo = this.head; // o novo nó "engata" no vagão que era o primeiro
        this.head = novoNo;         // o novo nó passa a ser a locomotiva do trem
        this.tamanho++;
    }

    // ------------------------------------------------------------------
    // 3.1) INSERÇÃO NO FIM — custo O(n)
    // ------------------------------------------------------------------
    // Para inserir no fim, precisamos "andar" pela lista até encontrar
    // o último nó (aquele cujo "proximo" é null) e então conectá-lo
    // ao novo nó.
    public void inserirNoFim(String dado) {
        No novoNo = new No(dado);

        // Caso especial: lista vazia -> o novo nó vira a própria head
        if (this.head == null) {
            this.head = novoNo;
            this.tamanho++;
            return;
        }

        // Percorremos a lista a partir da head até achar o último vagão
        No atual = this.head;
        while (atual.proximo != null) {
            atual = atual.proximo;
        }

        // "atual" agora é o último nó -> conectamos o novo nó a ele
        atual.proximo = novoNo;
        this.tamanho++;
    }

    // ------------------------------------------------------------------
    // MÉTODO AUXILIAR: exibir tamanho atual (útil para os testes)
    // ------------------------------------------------------------------
    public int getTamanho() {
        return this.tamanho;
    }

    // TODO (Missão do Aluno): implemente aqui os métodos pedidos na Seção 4!

    // ------------------------------------------------------------------
    // MÉTODO MAIN: testando nossa lista
    // ------------------------------------------------------------------
    public static void main(String[] args) {
        ListaEncadeada historico = new ListaEncadeada();

        historico.inserirNoFim("Digitou 'Olá'");
        historico.inserirNoFim("Digitou 'Olá, mundo'");
        historico.inserirNoInicio("Abriu o documento"); // deve virar a primeira ação

        System.out.println("Tamanho atual do histórico: " + historico.getTamanho());
        // Próximo passo: implemente exibirLista() para ver o resultado completo!
    }
}
```

## 4. 🚀 Missão do Aluno (O Projeto)

Agora é com você! O código acima te deu a fundação (a classe `No`, a `head` e os dois métodos de inserção). Sua missão é **completar** a implementação com os seguintes métodos, dentro da própria classe `ListaEncadeada`:

### Missão 3 — `deletar(String dado)` (o desafio mais difícil!)
Implemente um método que remova o **primeiro nó** que contenha o dado informado. Preste atenção a dois casos especiais:
- E se o nó a ser removido for o **primeiro** da lista (a `head`)?

> 💡 Dica: para remover um nó do meio ou do fim, você precisa manter uma referência para o nó **anterior** ao nó que será removido, e então fazer `anterior.proximo = atual.proximo` — "pulando" o nó indesejado, como desengatar um vagão do trem e reconectar os vizinhos dele.

**Critério de sucesso:** ao final, seu `main()` deve simular um cenário completo de "desfazer/refazer" — inserindo, exibindo, buscando e deletando ações do histórico — sem lançar nenhuma exceção.
